# LunaOS v1 et Try Luna — plan de release

Ce plan remplace le hors-périmètre de la section « Hors périmètre, assumé » du design. Il a été demandé le 2026-11-06 : une v1 complète (paquets, ISO, installation) et Try Luna (préversion macOS Apple Silicon). Chaque phase ne se termine que lorsque ses vérifications ont été exécutées et leurs logs lus. Le statut courant reste dans [`lunaos/docs/STATUS.md`](../STATUS.md).

## Points de départ dans l'historique

Ces pièces existent dans `7ec50f4a` et n'ont pas été importées. Elles ne doivent pas être repris sans relecture, comme pour la phase 0 :

- `lunaos/packaging/control-plane/PKGBUILD` et `build-signed-repo.sh` : paquet du plan de contrôle et dépôt signé.
- `lunaos/packaging/keys/lunaos-packages.asc` : clé **publique** du dépôt (la clé privée n'est jamais dans le dépôt).
- `lunaos/packaging/arch/`, `lunaos/scripts/build-archiso.sh`, `test-iso-*.sh` : profil archiso et tests d'installation. Le profil est **x86_64 seulement** (`packages.x86_64`).
- `try-luna/` : overlay et patch pour la préversion macOS.
- `lunaos/docs/superpowers/specs/2026-10-26-standalone-installable-iso-design.md` et son plan.

## Phases

1. **Paquet du plan de contrôle.** Adapter le PKGBUILD aux chemins réels : binaires `/usr/bin/luna-*`, unités, sysusers, manifeste `/usr/share/luna-inference/manifest.json`, environnement optionnel. Le hook `lunaos-services.sh` déjà en place s'applique à ce paquet.
   Vérification : `makepkg` dans `archlinux:latest`, `systemd-analyze verify`, `make test-process-linux`, et installation dans une VM.
2. **Dépôt signé.** Décision requise sur la gestion de la clé de signature (voir blocages). Aucune clé privée dans le dépôt, aucune lecture de `.lunaos-signing/`.
3. **Installeur et ISO.** Reprendre le profil archiso, le limiter à ce qui est testé. Vérification : construction, démarrage et installation complète dans une VM ; `test-iso-install.sh` lu jusqu'au bout.
4. **Bureau.** Session Wayland dans la VM : barre, widget LUNA, `lunaos-luna status`, raccourci STOP LUNA, rendu des captures. Vérification visuelle selon `agents/skills/visual-verification.md`.
5. **Try Luna (macOS Apple Silicon).** Overlay et patch depuis `try-luna/`, construction de la machine invitée. Demande une machine Apple Silicon avec les outils de virtualisation. Toute installation sur l'hôte demande accord explicite.
6. **Stabilisation et release.** Suites Linux (`make test check test-process-linux`, `./test/all`, tests shell) dans un environnement Linux, sans échec non expliqué. Tag `v1.0.0` seulement après ces trois points.

## Blocages à lever avant la phase 1

- **Environnement Linux** : une VM est annoncée. Il faut son type (QEMU, UTM, VMware), son architecture et la manière d'y accéder (SSH, console). Ce Mac est arm64 ; l'ISO actuelle est x86_64. Une VM x86_64 sous émulation est lente ; une VM aarch64 ne produit pas l'ISO actuelle.
- **Signature** : qui détient la clé privée du dépôt, et où elle sera utilisée. Le dépôt ne la contient pas.
- **Try Luna** : accord pour installer les outils de virtualisation et de construction sur ce Mac.

## Ce qui n'est pas garanti

Une « v1 stable » ne peut pas être affirmée tant que les phases 3 à 6 ne sont pas exécutées sur Linux. Chaque phase qui échoue sera notée dans STATUS.md, sans être masquée.
