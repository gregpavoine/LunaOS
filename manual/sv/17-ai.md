# AI

LunaOS behandlar AI-kodagenter som förstklassiga medborgare, men det väljer ingen favorit åt dig. I stället är varje större CLI för kodagenter förkopplat som en latladdad startfil. Startfilerna är små stubbar i `~/.local/bin/` som hanteras av [mise](https://mise.jdx.dev/), så ingenting laddas ner förrän första gången du faktiskt kör en. Hermes är undantaget: för den stubbas ingenting, och att välja den installerar Hermes Desktop, som _Skrivbordsappar_ nedan förklarar. Kör någon av dem och autentisera dig när du blir ombedd:

| Kommando   | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) från xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Mario Zechners Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouters harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), Nous Researchs agent  |
| `muse`     | [Muse Code](https://dev.meta.ai), Metas kodagent           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` är den udda i gänget: den kör de andra harnessarna mot hela OpenRouters modellkatalog, så `ori claude`, `ori codex` eller `ori opencode` startar de agenterna på vilken modell du än pekar dem mot, och `ori code` är Oris egen agent.

För att koppla in ett ytterligare CLI på samma sätt kör du `lunaos-mise-install <package> [command-name]`. Stubbarna hålls aktuella tillsammans med allt annat som mise hanterar när du kör `lunaos update` (eller aliaset `mup`).

`grok` installeras genom mises förstapartspaket `grok`, på samma sätt som `claude` och `codex`. Kör `grok`, eller välj den under _Setup > Defaults > Agent_. Hoppa över `curl | bash`-installeraren på x.ai. Den vägen lägger en andra kopia i `~/.grok/bin`, sätter den först på `PATH` och skriver över LunaOSs omslag.

### Standardagenten

Välj din standardagent med `lunaos default agent <name>` eller under _Setup > Defaults > Agent_ i LunaOS-menyn (`Super + Space`). Om agenten inte är installerad än installerar valet av den den först. Ett färskt LunaOS bjuder in dig att göra det här valet med en engångsavisering.

Att välja Claude försöker också konfigurera dess webbläsartillägg för Chromium, Chrome, Brave, Brave Origin och Edge. Tilläggsinställningen gäller alla användare och kan be om ditt systemlösenord; att avbryta eller att en tilläggsinstallation misslyckas väljer och startar fortfarande Claude. Starta om din webbläsare, aktivera tillägget om du blir ombedd och logga in på Claude för att slutföra anslutningen av det. Kör `/chrome` i Claude för att kontrollera anslutningen. Firefox och Zen stöder inte det här tillägget. Om Claude redan var din standard innan den här konfigurationen lades till väljer du den igen för att installera tillägget.

[Muse Code](https://dev.meta.ai) — Metas `muse` — använder en förinstallerad mise-stubb precis som de andra agenterna. Att välja den som standard installerar Metas officiella startfil genom mises HTTP-backend. Startfilen verifierar och uppdaterar den nativa binären för din dator.

När du har valt startar `Super + Shift + Ctrl + A` standardagenten i ett dedikerat terminalfönster (eller tar fram väljaren om du inte har valt än). Du kan också starta den rakt in i en uppgift med `lunaos agent prompt "Review this project"`. Agenter som startas på det här sättet kör obevakade i sina respektive lägen där de inte stannar för att fråga, så var redo på att de faktiskt gör saker! Och eftersom agenter vägrar att komma ihåg tillit för din hemkatalog startar starter från `$HOME` i stället i `~/Work`.

Det finns terminalgenvägar också: `a` kör standardagenten inline i den aktuella terminalen, medan `c`, `cx` och `cy` startar OpenCode, Claude Code och Codex direkt (också i sina auto-godkännande lägen). Temabyten synkar också till agenterna: Claude Code, Pi, OpenCode och Hermes (när LunaOS har installerat den) följer alla med när du byter LunaOS-tema.

### Agentpanelen

I den övre panelen finns en agentikon. Innan du har ställt in en agent går dess panel igenom inloggningen till Claude, Codex eller Grok med dig, och den första blir din standardagent. Efter det samlar panelen varje prenumeration på en sida: varje agent och konto med sin plan, en mätare för var och en av dess 5-timmes sessionsgräns och veckogräns med tiden tills den återställs (hovra för den exakta procentsatsen), eller det återstående förbetalda saldot, under en rad som roterar genom det du har använt i alla dem, som tokens den här veckan och din mest använda modell. Under _Make something_ erbjuder den startpromptar för ett nytt tema, plugin eller en ny app som lämnar över uppgiften till din standardagent. Appar byggs på samma sätt som LunaOSs egna Hype, Monologue och Omacut, i C++ och Qt Quick, enligt agentskillen lunaos-app, och kompilatorn och Qt-delarna de behöver följer med installerade. Claude Code, Codex, Grok, Fireworks och Kimi täcks direkt ur lådan. Kimi rapporterar för närvarande kontokvotsgränser utan lokal token- eller promptstatistik.

Vänsterklicka på ikonen i panelen för panelen, högerklicka för att starta din standardagent. Användningsposterna bakom den genereras om var 15:e minut av `lunaos agent usage-update`, och panelen kan till och med slå ihop användning från dina andra datorer via en synkad mapp. Se README under `$LUNAOS_PATH/shell/plugins/agents/` för de fullständiga inställningarna.

### Flera prenumerationer

Om du betalar för mer än en Claude-, Codex- eller Grok-plan — till exempel en personlig Max och en för jobbet — kan LunaOS hålla dem alla inloggade och flytta mellan dem. Lägg till en prenumeration med + i agentpanelen, som går igenom det med dig där och då, eller med `lunaos agent account add claude Work` (eller `codex`, eller `grok`). Det installerar CLI:t om det saknas. Det första kontot för en leverantör loggar in genom din vanliga webbläsare, precis där CLI:t alltid tittar. Varje konto därefter loggar in genom ett privat fönster, så kontot din webbläsare redan är inloggad på inte tas upp av misstag; logga in där som kontot du lägger till, och stäng först varje privat fönster du redan hade öppet. Logga aldrig ut ur CLI:t för att göra det här: utloggning återkallar den sparade inloggningen, och det kontot skulle behöva läggas till igen.

För att kopiera dina prenumerationsinloggningar till en annan LunaOS-dator över SSH kör du `lunaos agent account copy user@laptop`. Avsändaren tillhandahåller en tillfällig mottagare när destinationen inte har någon installerad, så äldre LunaOS-datorer kan ta emot konton utan en uppdatering. Installerade mottagare har företräde. Det här kopierar alla Claude-, Codex- och Grok-prenumerationer; lägg till leverantörsnamn för att välja dem, som i `lunaos agent account copy laptop claude`. Kontonamn och kommando-ID:n matchar källan, inklusive konton som redan finns på destinationen. Orelaterade destinationskonton får ett numeriskt suffix om deras namn krockar, och inställningar, skills, plugins och konversationshistorik stannar lokalt på varje dator.

Befintliga destinationsuppgifter behålls. Ett källkonto som redan är inloggat där får sitt namn synkroniserat utan att dess uppgifter ersätts; andra konton läggs till bredvid det. För att ersätta sparade uppgifter för matchande konton använder du `lunaos agent account copy --replace laptop claude` efter att ha avslutat det kontots sessioner på destinationen. En färsk destination får också källans aktiva konto och växlingsinställningar; en etablerad destination behåller sina egna.

Uppgifter färdas genom SSH och lagras i privata filer på destinationen, så kopiera bara till datorer du litar på. Det här är en engångskopiering, inte pågående synkronisering. Codex-uppdateringstokens kan roteras av en annan dator, vilket lämnar en kopierad inloggning i behov av förnyelse; separata inloggningar är fortfarande det mest pålitliga valet för samtidig användning på flera datorer. Se [Codexs vägledning för kontoautentisering](https://developers.openai.com/codex/auth/ci-cd-auth).

Ett konto per leverantör är aktivt, och varje ny session startar som det: `cx`, `cy`, ett vanligt `claude`, `codex` eller `grok`, allting som startas genom `lunaos agent`, och skript eller editorer som hittar CLI:t på `PATH`. Växla med `lunaos agent account use work` (och tillbaka med `lunaos agent account use main`), eller i panelen genom att trycka på ett kontos nummer och sedan `Enter` (eller klicka på dess Use-knapp). Sessioner som redan kör stannar på kontot de startade med. Konversationshistorik, inställningar, skills och plugins delas mellan konton, så `claude --continue` i samma mapp fortsätter där du slutade på det nya kontot.

Med mer än ett konto visar panelen varje kontos gränser sida vid sida, med det aktiva markerat. Som standard aviserar LunaOS dig när det aktiva kontot passerar 95 % av en gräns, och att klicka på aviseringen växlar till kontot med mest utrymme. Hovra över ett kontos rad i panelen och klicka på Autoswitch som dyker upp bredvid Use (eller tryck `m`), eller kör `lunaos agent account mode auto`, för att låta det växla på egen hand i stället; medan det är på tar Autoswitch Use:s plats, och att klicka på det igen går tillbaka till att avisera. Lägg till ett nummer för att ändra tröskeln, som i `lunaos agent account mode auto 90`. Om varje konto är över tröskeln får du höra om det en gång, tillsammans med vilket konto som frigörs först. Medan ett aktivt konto är inom 15 punkter från sin tröskel (80 % som standard) kontrolleras dess gränser var tredje minut snarare än var 15:e.

`lunaos agent account list` visar varje konto och dess senaste gränser, `lunaos agent account remove work` glömmer ett, och `lunaos agent account rename primary Hey` döper om ett (eller klicka på ett kontos namn i panelen). De här kommandona arbetar på din standardagents konton; för att nå den andra leverantören namnger du den först, som i `lunaos agent account use codex side`. Inloggningen du redan hade i `~/.claude` eller `~/.codex` är _Main_-kontot och stannar där den är. Ett konto som lämnas oanvänt i mer än ungefär åtta timmar kan visa _Sign-in required_; klicka på det för att logga in det kontot igen direkt i panelen, eller starta en session i det, vilket fräschar upp inloggningen på egen hand. MCP-servrar du hade när ett konto lades till följer med till det, men sådana du lägger till senare med `claude mcp add` når bara kontot du lade till dem i. Claude Desktop och verktyg som konfigurerats med en absolut sökväg till en CLI-binär följer inte växlingen. En explicit `CLAUDE_CONFIG_DIR`, `CODEX_HOME` eller `GROK_HOME` har företräde framför det valda kontot.

### Kraschdiagnos

LunaOS bevakar systemd-coredump för processkrascher. När någonting segfaultar får du en "Process crashed"-avisering — klicka på den, så lämnas kraschen över till din standardagent tillsammans med LunaOSs diagnose-crash-skill, som går igenom att fastställa fakta från coredumpen med agenten och avgöra om kraschen är värd att rapportera uppströms. Du kan också köra den för hand mot valfritt PID från `coredumpctl list` med `lunaos agent crash <pid>`.

Bevakningen är på som standard. Stäng av den under _Trigger > Toggle > Crash Capture_ (eller med `lunaos toggle crash-capture`) så slutar aviseringarna; `lunaos agent crash <pid>` fungerar fortfarande för hand.

Krascher kan också tystas ett program i taget, vilket är vad diagnosen erbjuder dig i slutet. `lunaos crash mute hyprland` stoppar aviseringarna för bara det programmet, `lunaos crash mute hyprland off` tar tillbaka dem, och `lunaos crash mute` på egen hand listar vad du har tysstat. Det tar binärens sökväg lika glatt som dess namn, så `lunaos crash mute /usr/bin/hyprland` gör samma sak. Citera ett namn med ett mellanslag i det, som i `lunaos crash mute 'Some App'`. Allt annat aviserar fortfarande, och det tystade programmet kraschar fortfarande — det här döljer påminnelsen, det fixar ingenting.

### Skrivbordsappar

Menyn _Install > AI_ bär också några grafiska AI-appar: ChatGPT-skrivbordsappen, Claude-skrivbordsappen (Anthropics Linux-beta, med flikarna Chat, Cowork och Claude Code), Grok Bot för att chatta med xAI:s modeller, Hermes Desktop, OpenClaw och Perplexity-skrivbordsappen. Grok Bot är skrivbordschattappen. Kodagenten är kommandot `grok`.

Hermes Desktop är den att känna till, för en dator har en Hermes, och den är appens: Hermes installeras bara någonsin genom appen, och kommandot `hermes` som standardagenten kör är appens. Att välja Hermes som standardagent installerar samma sak som posten i _Install > AI_ gör: paketet, och en Hermes-runtime under `~/.hermes` som ställs in av Hermes egna installerare, vilket tar några minuter första gången. Den runtimen är den enda Hermes som terminalkommandot `hermes`, standardagenten och appen alla använder, och den uppdaterar sig själv med `hermes update` snarare än att vänta på en LunaOS-utgåva. Att installera den ger också Hermes LunaOS-temat som ett skin med namnet `lunaos`, som varje Hermes-yta följer när du byter teman; välj en annan under Hermes Appearance-inställningar eller med `/skin` om du hellre vill att den inte gör det, så lämnar LunaOS det valet i fred. Att ta bort appen under _Remove > AI_ stänger Hermes först, gatewayen inkluderad, tar med sig den runtimen, och behåller dina chattar, minnen och skillsen Hermes skrev för sig själv om du inte säger annat: den frågar, med nej som standard, om de uppgifterna och dina anslutningsinställningar ska bort också.

OpenClaws skrivbordsupplevelse är dess Control UI, som öppnas som en webbapp som backas av dess egen lokala gateway. OpenClaw bor i `~/.openclaw` och uppdaterar sig själv: använd Control UI:s "Update Gateway"-knapp eller kör `openclaw update`, så startar gatewayen om på den nya versionen. LunaOS väljer bara utgåvan en färsk installation startar från. Att ta bort OpenClaw under _Remove > AI_ tar med sig gatewaytjänsten och appen och frågar sedan om `~/.openclaw` ska bort också, eftersom den rymmer dina chattar och uppgifter bredvid OpenClaw själv och plugin-runtimesen den laddar ner; standarden behåller den, och att installera OpenClaw igen plockar upp den igen.

### Lokala LLM:er

LunaOS rekommenderar två sätt att köra lokala LLM-modeller: LM Studio och Ollama. LM Studio tillhandahåller ett GUI-gränssnitt för att hitta modeller med öppna vikter, installera dem och köra dem. Det är ett utmärkt sätt att komma igång enkelt. Ollama erbjuder ett CLI för att göra det på liknande sätt. Men om du är ny på lokala modeller skulle jag börja med LM Studio. Du kan installera endera under _Install > AI_ i LunaOS-menyn.

### LunaOS-skillen

Agentskills hjälper AI att använda specifika verktyg på ett specifikt sätt, och LunaOS levereras med en standardskill för att skräddarsy systemet. Som att justera din Hyprland-konfig, justera panelen, eller till och med skapa ett nytt tema från grunden. Den är symlänkad in i skillkatalogerna för Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` och varje `~/.hermes/profiles/*/skills`) och den generiska platsen `~/.agents/skills`, så de flesta harnessar plockar upp den automatiskt.

Men du bör behandla den här skillen som experimentell. Olika modeller kommer att använda den med olika effekt. Det är bäst att köra i planläge först, så du har en uppfattning om vad agenten skulle vilja ändra. Och var sedan redo att rulla tillbaka ändringar eller till och med köra `lunaos reinstall configs`, om agenten ställer till med en röra av allt.
