# การอัปเดต

LunaOS และแพ็กเกจของคุณถูกเก็บให้เป็นปัจจุบันอยู่เสมอผ่าน _อัปเดต > LunaOS_ ในเมนู LunaOS (`Super + Space`)

ตัว LunaOS เองติดตั้งเป็นแพ็กเกจ pacman ปกติจาก [ที่เก็บแพ็กเกจ LunaOS](https://github.com/omacom-io/omarchy-pkgs) ดังนั้นการอัปเดตจึงติดตั้ง [รุ่นล่าสุดของ LunaOS](https://github.com/gregpavoine/LunaOS/releases) รันการย้ายที่ค้างอยู่เพื่อให้ระบบของคุณซิงค์กับรุ่นล่าสุด และอัปเดตแพ็กเกจระบบทั้งหมดจาก [มิเรอร์ Arch ของ LunaOS](https://github.com/omacom-io/omarchy-mirror) และ [AUR](https://aur.archlinux.org/) (ถ้าคุณติดตั้งแพ็กเกจ AUR ไว้บ้าง)

เมื่อมีรุ่นใหม่ออกมา ไอคอนลูกศรวงกลมจะโผล่ขึ้นมาทางขวาของนาฬิกาคุณ คลิกมันแล้วกระบวนการอัปเดตจะเริ่ม

![update-available](images/update-available.webp)

### สี่ช่องทาง

LunaOS อัปเดตตามสี่ช่องทาง stable, RC, edge และ dev การติดตั้งใหม่เริ่มบนช่อง stable ซึ่งติดตาม [รุ่นอย่างเป็นทางการ](https://github.com/gregpavoine/LunaOS/releases/) รวมถึง [มิเรอร์ Arch รุ่น stable ของ LunaOS](https://github.com/omacom-io/omarchy-mirror) ที่ช้ากว่ารุ่นล่าสุดหนึ่งเดือน เพื่อให้เราจับความไม่เข้ากันใหม่ ๆ ที่ต้องเปลี่ยนคอนฟิกก่อนที่พวกมันจะสร้างปัญหาให้ผู้คนได้

แต่ถ้าคุณอยากช่วยเห็นปัญหาที่อาจเกิดขึ้นเหล่านั้น คุณสามารถรันบนช่อง edge ได้ นั่นจะทำให้แพ็กเกจ LunaOS ของคุณติดตามรุ่นพัฒนาล่าสุด และให้คุณอัปเดตไปแพ็กเกจ Arch ล่าสุดทันทีที่มีให้ คุณควรทำสิ่งนี้เฉพาะถ้าคุณมีประสบการณ์กับ Linux เท่านั้น และรู้วิธีกู้ระบบที่มีปัญหา

ก่อนรุ่นหลักใหม่ใด ๆ เราจะทำการตรวจสอบขั้นสุดท้ายโดยใช้ช่อง RC ถ้าคุณสนใจช่วยขัดเกลาขั้นสุดท้าย มาอยู่ใน #lunaos-release-candidates บน Discord ได้เลย

สุดท้าย มีช่อง dev ซึ่งเชื่อม LunaOS โดยตรงไปยัง git checkout ของซอร์สโค้ดใน `~/lunaos` รวมกับแพ็กเกจ edge คุณควรใช้ช่องนี้เฉพาะถ้าคุณเป็นผู้ใช้ Linux ที่มีประสบการณ์ ทำงานบน LunaOS โดยตรง และเต็มใจทนกับการแตกหักเท่านั้น

คุณสามารถสลับระหว่างช่องทางโดยใช้ _อัปเดต > Channel_ จากเมนู LunaOS (หรือ `lunaos-channel-set` ในเทอร์มินัล)

### การอัปเดตเฟิร์มแวร์

แพ็กเกจของคุณไม่ใช่สิ่งเดียวที่ล้าสมัย แล็ปท็อปและอุปกรณ์เสริมหลายตัวส่งเฟิร์มแวร์ BIOS, SSD และ dock ผ่าน Linux Vendor Firmware Service และ _อัปเดต > Firmware_ ในเมนู LunaOS จะดึงและติดตั้งอะไรก็ตามที่ฮาร์ดแวร์ของคุณรออยู่ มันติดตั้ง `fwupd` ในครั้งแรกที่คุณรันมัน เฟิร์มแวร์มากมายเขียนได้เฉพาะระหว่างรีบูตเท่านั้น ดังนั้นอย่าแปลกใจหากถูกขอให้รีบูต

### คำเตือนเกี่ยวกับการอัปเดต pacman/yay โดยตรง

ถ้าคุณคุ้นเคยกับ Arch อยู่แล้ว คุณอาจถูกยั่วยวนให้แค่รัน `pacman -Syu` หรือ `yay -Syu` เอง แต่ถ้าคุณทำอย่างนั้น คุณจะพลาด snapshot การย้าย และการอัปเดตการกำหนดค่าที่ LunaOS รันร่วมกับแพ็กเกจใหม่ นั่นคือเหตุผลที่ LunaOS จะหยุดการอัปเกรดระบบโดยตรงและชี้คุณไป `lunaos update` แทน (ถ้าคุณรู้จริง ๆ ว่ากำลังทำอะไร ตัวป้องกันจะบอกวิธีข้ามมันสำหรับธุรกรรมเดียวให้คุณ)

### การย้อนกลับการอัปเดตที่ไม่ดี

ถ้าคุณเคยมีปัญหาหลังจากอัปเดต คุณสามารถย้อนกลับระบบของคุณไป snapshot ที่ถ่ายไว้ก่อนการอัปเดตได้ แค่รีสตาร์ตและเลือก snapshot ในเมนูโหลดบูตจากก่อนที่คุณจะเริ่มอัปเดต

![bootloader](images/bootloader.webp)

ถ้าไฟล์การกำหนดค่าของคุณเสียหายด้วยวิธีใดวิธีหนึ่ง คุณสามารถทำการติดตั้ง LunaOS ใหม่โดยใช้ `lunaos reinstall` ในเทอร์มินัลได้ด้วยเช่นกัน สิ่งนี้จะติดตั้งแพ็กเกจ LunaOS เริ่มต้นทั้งหมดใหม่ ให้คุณอยู่บน stable และดาวน์เกรดแพ็กเกจใด ๆ ที่ใหม่เกินไป และรีเซ็ตไฟล์การกำหนดค่าทั้งหมด โปรดทราบว่าการเปลี่ยนแปลงคอนฟิกผู้ใช้ทั้งหมดของคุณต่อค่าเริ่มต้นของ LunaOS จะถูกเขียนทับเมื่อทำสิ่งนี้!
