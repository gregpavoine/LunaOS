# AI

LunaOS は AI コーディングエージェントを一級市民として扱うが、あなたのお気に入りを勝手に決めてはくれない。代わりに、主要なコーディングエージェント CLI はすべて、遅延読み込みされるランチャーとしてあらかじめ組み込まれている。これらのランチャーは `~/.local/bin/` に置かれた [mise](https://mise.jdx.dev/) 管理の小さなスタブなので、実際に初めて実行するまで何もダウンロードされない。Hermes は例外だ。Hermes 用のスタブは存在せず、Hermes を選ぶと Hermes Desktop がインストールされる。以下の _デスクトップアプリ_ で説明する通りだ。どれかを起動し、求められたら認証してくれ:

| コマンド    | エージェント                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | xAI の [Grok Build](https://x.ai/build)                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Mario Zechner の Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | OpenRouter のハーネス [Ori](https://openrouter.ai/docs/guides/ori/harness) |
| `hermes`   | Nous Research のエージェント [Hermes](https://hermes-agent.nousresearch.com/)  |
| `muse`     | Meta のコーディングエージェント [Muse Code](https://dev.meta.ai)           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` は異色の存在だ。他のハーネスを OpenRouter のモデルカタログ全体に対して実行するので、`ori claude`、`ori codex`、`ori opencode` は、指定したどのモデル上でもそれらのエージェントを起動できる。そして `ori code` が Ori 独自のエージェントだ。

追加の CLI を同じ方法でラップするには、`lunaos-mise-install <package> [command-name]` を実行する。スタブは、`lunaos update`（あるいは `mup` エイリアス）を実行すると、mise が管理する他のすべてと一緒に最新の状態に保たれる。

`grok` は、`claude` や `codex` と同じ方法で、mise のファーストパーティ `grok` パッケージ経由でインストールされる。`grok` を実行するか、_設定 > デフォルト > エージェント_ で選んでくれ。x.ai の `curl | bash` インストーラは使わないこと。その方法だと `~/.grok/bin` に2つ目のコピーが置かれ、`PATH` の先頭に追加され、LunaOS のラッパーを上書きしてしまう。

### デフォルトのエージェント

デフォルトのエージェントは `lunaos default agent <name>` で選ぶか、LunaOS Menu（`Super + Space`）の _設定 > デフォルト > エージェント_ で選ぶ。エージェントがまだインストールされていなければ、選ぶことでまずインストールされる。新しくインストールした LunaOS では、一度だけの通知でこの選択を促される。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 向けにそのブラウザ拡張機能のセットアップも試みる。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められる場合がある。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude の選択と起動は行われる。ブラウザを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了させてくれ。Claude 内で `/chrome` を実行すれば接続を確認できる。Firefox と Zen はこの拡張機能に対応していない。このセットアップが追加される前から Claude がデフォルトだった場合は、拡張機能をインストールするためにもう一度選んでくれ。

[Muse Code](https://dev.meta.ai)——Meta の `muse`——は、他のエージェントと同様にプリインストールされた mise スタブを使う。デフォルトとして選ぶと、mise の HTTP バックエンド経由で Meta 公式ランチャーがインストールされる。そのランチャーが、あなたのマシン向けのネイティブバイナリを検証し、更新する。

一度選べば、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウにデフォルトのエージェントが起動する（まだ選んでいなければピッカーが表示される）。`lunaos agent prompt "Review this project"` のように、タスクを直接渡して起動することもできる。この方法で起動されたエージェントは、それぞれの「途中で聞きに来ない」モードで無人で動作するので、本当にあれこれ実行し始める覚悟をしておくこと！そしてエージェントはホームディレクトリへの信頼を覚えることを拒否するので、`$HOME` からの起動は代わりに `~/Work` で始まる。

ターミナルのショートカットもある。`a` は現在のターミナル内でデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（こちらも自動承認モードだ）。テーマの変更もエージェントに同期される。Claude Code、Pi、OpenCode、Hermes（LunaOS がインストールした後）はすべて、LunaOS のテーマを切り替えると追従する。

### エージェントパネル

トップバーにはエージェントアイコンがある。エージェントをセットアップする前は、そのパネルが Claude、Codex、Grok へのサインインを案内し、最初にサインインしたものがデフォルトのエージェントになる。その後は、このパネルですべてのサブスクリプションが1ページにまとまる。各エージェントとアカウントにそのプランが表示され、5時間セッション制限と週間制限のそれぞれにメーターとリセットまでの時間が表示され（正確なパーセンテージはホバーで確認できる）、あるいはプリペイド残高が表示される。その上に、すべてのエージェントを通じた使用状況——今週のトークン数や最もよく使っているモデルなど——が切り替わりながら表示される行がある。_何かを作る_ の下には、新しいテーマ、プラグイン、アプリ向けのスタータープロンプトがあり、タスクをデフォルトのエージェントに渡してくれる。アプリは LunaOS 自身の Hype、Monologue、Omacut と同じ作り方、C++ と Qt Quick で、lunaos-app エージェントスキルに従って構築される。必要なコンパイラと Qt の部品はインストール済みだ。Claude Code、Codex、Grok、Fireworks、Kimi はそのままで対応している。Kimi は現在、ローカルのトークンやプロンプトの統計なしでアカウントのクォータ制限を報告する。

バーアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動する。その背後にある使用記録は、`lunaos agent usage-update` によって15分ごとに再生成される。パネルは同期フォルダ経由で他のマシンからの使用状況を統合することさえできる。設定の詳細は `$LUNAOS_PATH/shell/plugins/agents/` の README を参照してほしい。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数払っている場合——例えば個人の Max と仕事用——LunaOS はそれらすべてにサインインしたまま切り替えて使うことができる。サブスクリプションは、エージェントパネルの + からその場で案内に従って追加するか、`lunaos agent account add claude Work`（あるいは `codex`、`grok`）で追加する。CLI がなければインストールされる。プロバイダの最初のアカウントは、CLI が常に参照する場所で、通常のブラウザを通じてサインインする。その後のアカウントはすべてプライベートウィンドウを通じてサインインするので、ブラウザで既にサインインしているアカウントを誤って拾ってしまうことはない。そこでは追加するアカウントとしてサインインし、既に開いているプライベートウィンドウがあれば先に閉じておいてくれ。この作業のために CLI からログアウトしてはいけない。ログアウトすると保存されたサインインが失効し、そのアカウントを再び追加し直さなければならなくなる。

サブスクリプションのログインを SSH 経由で別の LunaOS マシンにコピーするには、`lunaos agent account copy user@laptop` を実行する。送信側は、宛先に受信側がインストールされていない場合、一時的な受信側を提供するので、古い LunaOS マシンでも更新なしにアカウントを受け取ることができる。インストール済みの受信側が優先される。これはすべての Claude、Codex、Grok サブスクリプションをコピーする。`lunaos agent account copy laptop claude` のようにプロバイダ名を追加すれば選ぶことができる。アカウント名とコマンド ID は、宛先に既に存在するアカウントを含め、送信元と一致する。宛先の無関係なアカウントで名前が競合する場合は数字のサフィックスが付き、設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残る。

宛先に既にある認証情報は保持される。送信元アカウントがそこで既にサインインしている場合、その名前は認証情報を置き換えることなく同期される。他のアカウントはその横に追加される。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了してから `lunaos agent account copy --replace laptop claude` を使う。新規の宛先には送信元のアクティブなアカウントと切り替え設定も渡される。既に使い込まれた宛先は自身の設定を保持する。

認証情報は SSH を経由して移動し、宛先ではプライベートファイルに保存される。だからコピー先は信頼できるマシンだけにしてくれ。これは一度きりのコピーであり、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンによってローテーションされる場合があり、コピーしたログインの更新が必要になることがある。複数マシンで同時に使うなら、別々にサインインするのが依然として最も確実な選択だ。[Codex のアカウント認証に関するガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してほしい。

プロバイダごとに1つのアカウントがアクティブになり、すべての新しいセッションはそのアカウントで始まる。`cx`、`cy`、素の `claude`、`codex`、`grok`、`lunaos agent` 経由で起動されるもの、`PATH` 上で CLI を見つけるスクリプトやエディタがそうだ。切り替えは `lunaos agent account use work` で行い（戻すには `lunaos agent account use main`）、あるいはパネルでアカウントの番号を押してから `Enter` を押す（あるいはその Use ボタンをクリックする）。既に実行中のセッションは、開始したアカウントのまま残る。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` を実行すれば、新しいアカウント上で前回の続きから再開できる。

複数のアカウントがある場合、パネルには各アカウントの制限が横並びで表示され、アクティブなものに印が付く。デフォルトでは、アクティブなアカウントが制限の95%を超えると LunaOS が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わる。代わりに自動で切り替えたい場合は、パネルでアカウントの行にホバーして Use の横に現れる Autoswitch をクリックするか（あるいは `m` を押す）、`lunaos agent account mode auto` を実行する。有効になっている間は Autoswitch が Use の場所を取り、もう一度クリックすると通知する方式に戻る。`lunaos agent account mode auto 90` のように数値を追加すればしきい値を変更できる。すべてのアカウントがしきい値を超えている場合は、どのアカウントが最初に空くかと合わせて一度だけ通知される。アクティブなアカウントがしきい値から15ポイント以内にある間（デフォルトでは80%）、その制限は15分ごとではなく3分ごとに確認される。

`lunaos agent account list` はすべてのアカウントとその最新の制限を表示し、`lunaos agent account remove work` は1つを削除し、`lunaos agent account rename primary Hey` は1つの名前を変更する（あるいはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作する。他のプロバイダに届くには、`lunaos agent account use codex side` のように先に名前を指定する。`~/.claude` や `~/.codex` に元々あったログインが _Main_ アカウントであり、その場に残る。8時間ほど使われていないアカウントは _サインインが必要_ と表示される場合がある。それをクリックすればパネル内でそのアカウントに再びサインインでき、あるいはそのアカウントでセッションを開始すればサインインが自動的に更新される。アカウントが追加された時点で持っていた MCP サーバーはそのアカウントにも引き継がれるが、後で `claude mcp add` で追加したものは、追加したアカウントにしか届かない。Claude Desktop や CLI バイナリへの絶対パスで設定されたツールは、この切り替えに追従しない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択されたアカウントより優先される。

### クラッシュ診断

LunaOS は systemd-coredump でプロセスのクラッシュを監視している。何かが segfault すると「プロセスがクラッシュしました」という通知が来る——それをクリックすると、そのクラッシュは LunaOS の diagnose-crash スキルと一緒にデフォルトのエージェントに渡される。このスキルは、コアダンプから事実を確立し、そのクラッシュを上流に報告する価値があるかどうかを判断する手順をエージェントに案内する。`coredumpctl list` の任意の PID に対して、`lunaos agent crash <pid>` で手動で実行することもできる。

監視はデフォルトでオンだ。_トリガー > 切り替え > クラッシュキャプチャ_ でオフにするか（あるいは `lunaos toggle crash-capture` で）、通知が止まる。`lunaos agent crash <pid>` は手動では依然として使える。

クラッシュはプログラムごとに黙らせることもでき、それが診断の最後に提案されるものだ。`lunaos crash mute hyprland` はそのプログラムだけの通知を止め、`lunaos crash mute hyprland off` はそれを戻し、`lunaos crash mute` 単体ではミュートしたものの一覧が表示される。名前と同じくらいバイナリのパスも喜んで受け付けるので、`lunaos crash mute /usr/bin/hyprland` でも同じことができる。空白を含む名前は、`lunaos crash mute 'Some App'` のように引用符で囲む。残りはすべて通知され続け、ミュートしたプログラムは相変わらずクラッシュする——これはリマインダーを隠すだけで、何も直しはしない。

### デスクトップアプリ

_インストール > AI_ メニューにはグラフィカルな AI アプリもいくつか用意されている。ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ、Chat、Cowork、Claude Code のタブ付き）、xAI のモデルとチャットする Grok Bot、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリだ。Grok Bot はデスクトップチャットアプリだ。コーディングエージェントは `grok` コマンドの方である。

知っておくべきは Hermes Desktop だ。1台のマシンにある Hermes は1つだけで、それはアプリのものだからである。Hermes はアプリ経由でのみインストールされ、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトのエージェントに選ぶと、_インストール > AI_ の項目と同じものがインストールされる。そのパッケージと、Hermes 自身のインストーラが `~/.hermes` の下にセットアップする Hermes ランタイムで、初回は数分かかる。そのランタイムが唯一の Hermes であり、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてがそれを使い、LunaOS のリリースを待たずに `hermes update` で自ら更新する。インストールすると、LunaOS テーマが `lunaos` という名前のスキンとして Hermes に渡され、テーマを切り替えるたびに Hermes のあらゆる画面が追従する。それが気に入らなければ、Hermes の Appearance 設定か `/skin` で別のものを選んでくれ。LunaOS はその選択に干渉しない。_削除 > AI_ でアプリを削除すると、まずゲートウェイを含め Hermes を終了し、そのランタイムも一緒に取り除く。そして、そう指示しない限り、あなたのチャット、メモリ、Hermes が自分用に書いたスキルは保持される。そのデータと接続設定も一緒に削除するかどうかを、デフォルトは「いいえ」で尋ねてくる。

OpenClaw のデスクトップ体験はその Control UI で、自身のローカルゲートウェイに backed されたウェブアプリとして開く。OpenClaw は `~/.openclaw` に住み、自ら更新する。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイが新しいバージョンで再起動する。LunaOS は新規インストールが始まるリリースを選ぶだけだ。_削除 > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に取り除かれ、その後 `~/.openclaw` も削除するかどうかを尋ねられる。そこには OpenClaw 自体やダウンロードしたプラグインランタイムと並んで、あなたのチャットと認証情報が入っているからだ。デフォルトでは保持され、OpenClaw を再びインストールすればそれを再び拾い上げる。

### ローカル LLM

LunaOS はローカル LLM モデルを実行する方法として、LM Studio と Ollama の2つを推奨している。LM Studio は、オープンウェイトモデルを探し、インストールし、実行するための GUI インターフェースを提供する。気軽に始める素晴らしい方法だ。Ollama は同様のことを行うための CLI を提供する。だがローカルモデルが初めてなら、私は LM Studio から始めるだろう。どちらも LunaOS Menu の _インストール > AI_ からインストールできる。

### LunaOS Skill

エージェントスキルは、AI が特定のツールを特定の方法で使うのを助けるもので、LunaOS にはシステムをカスタマイズするためのデフォルトスキルが付属している。Hyprland の設定を微調整したり、バーを調整したり、ゼロから新しいテーマを作ったりといったことだ。このスキルは、Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` および各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` のスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスが自動的に拾い上げる。

だが、このスキルは実験的なものとして扱うべきだ。モデルによって効果はさまざまに変わる。まずプランモードで実行して、エージェントが何を変更したがっているのかを把握するのが最善だ。そして、エージェントがすべてをめちゃくちゃにしてしまったら、変更をロールバックしたり、さらには `lunaos reinstall configs` を実行したりする覚悟をしておくこと。
